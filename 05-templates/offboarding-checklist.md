# Offboarding Checklist

**Owner:** PM · **Trigger:** Client approves the final deliverable · **Cadence:** Once per project · **Last reviewed:** 2026-07-26

## Purpose

Close a project completely, so it stops consuming attention and money. An
un-offboarded project generates support requests forever and quietly carries
Alivio-owned costs for a client who no longer pays.

Process and reasoning: `../01-delivery/delivery-and-handoff.md`.

---

## Checklist

### Money — do this first
- [ ] **Final invoice issued the same day approval was received**
- [ ] All change orders invoiced
- [ ] Project profitability computed: revenue − contractor cost = margin
- [ ] Actual hours versus estimated recorded
- [ ] Unbilled scope changes totalled — the number worth knowing

### Handover
- [ ] Repositories transferred, or client added as owner
- [ ] Hosting, domains, DNS in client accounts
- [ ] Third-party services on client billing (analytics, CMS, email, AI providers)
- [ ] Credentials transferred via password manager — never chat or email
- [ ] Design source files delivered, organised, in the promised formats
- [ ] Handoff document written
- [ ] Handoff session held and recorded
- [ ] Client confirmed receipt **in writing**

### Alivio-owned costs
- [ ] **Every recurring cost Alivio is carrying for this client is either
      transferred, cancelled, or documented with an end date and an owner**
- [ ] API keys on Alivio accounts rotated or revoked
- [ ] Client removed from Alivio tools they no longer need

This section is the one that leaks money silently. An API key on Alivio's billing
for a client who left costs a little forever, and nobody ever notices it.

### Contractors
- [ ] Final contractor invoices received
- [ ] Contractor access to client systems revoked
- [ ] Anything only a contractor knew is written down

### Records
- [ ] Client folder in Obsidian complete: context, decisions, deliverables
- [ ] Post-mortem written — `../02-sales/win-loss-capture.md`
- [ ] Decision log current
- [ ] Linear project archived once Closed
- [ ] Portfolio permission confirmed — can Alivio show this work, and where

### Relationship
- [ ] Next step offered **once**: retainer, phase two, or nothing
- [ ] Testimonial or reference asked for, if it went well. Ask at approval, when
      goodwill peaks — not three months later
- [ ] Calendar reminder set for a check-in at [90 days]

### Close
- [ ] **Final invoice paid**
- [ ] Project moved to Closed

**Closed requires payment.** Delivered and Closed are different stages precisely so
a "finished" project cannot hide an unpaid invoice.

---

## Decision rights

- **PM decides alone:** running the checklist, handoff format.
- **Joel decides alone:** the final invoice, write-offs, whether to keep carrying
  any cost for the client.
- **Escalate when:** the client will not confirm approval in writing, or asks for
  "one more small thing" before signing off. The second is a scope change.

## Definition of done

Every box checked, final invoice paid, project Closed, and Alivio is carrying no
undocumented cost for this client.

## Assumptions

- Assumes clients take full ownership. Where Alivio continues hosting, that is a
  retainer with its own SOW — never a default that happens by neglect.
- Assumes a password manager exists. None is named in the stack; a gap.
- The 90-day check-in is a light-touch retention practice, not a sales sequence.
